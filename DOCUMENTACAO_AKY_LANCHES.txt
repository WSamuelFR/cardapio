1. VISÃO GERAL DO PROJETO
================================================================================
O AKY Lanches é uma solução completa desenvolvida para restaurantes, hamburguerias,
pizzarias e lanchonetes de atendimento presencial e delivery. 

O sistema integra em uma única plataforma:
- Cardápio digital interativo de alta conversão para clientes (mobile e desktop).
- Carrinho de compras com personalização rica de itens (sabores de pizzas,
  recheios de pastéis, adicionais, escolha de ponto e complementos).
- Checkout inteligente com cálculo de troco, opções de entrega e retirada,
  integração direta via WhatsApp e rastreamento de pedidos em tempo real.
- Painel Administrativo de Atendimento para controle dos pedidos recebidos.
- Sistema de KDS (Kitchen Display System) para visualização na cozinha, com
  destaque para ingredientes, filtros por cozinheiro e modo TV para telas grandes.
- Painel dedicado para motoboys gerenciarem suas entregas e coletarem confirmação.
- Sistema de avaliação e reputação com controle de privacidade dos comentários.
- Impressão configurável de cupons térmicos para a cozinha e expedição.
- Arquitetura Híbrida: Roda tanto na web (Docker / Cloud / MySQL) quanto como
  aplicativo desktop empacotado em Electron com PHP portátil embutido e
  espelhamento automático de backup para banco de dados local SQLite.

2. ARQUITETURA E TECNOLOGIAS UTILIZADAS
================================================================================
2.1. BACKEND & API:
- Framework: Laravel 11 / 13 (PHP 8.5+ x64)
- Padrão de Arquitetura: MVC com Controllers RESTful, Eloquent ORM e Service Layer
- Sessão / Autenticação: Sessões Laravel seguras, hash Bcrypt e CSRF Protection
- Conexões de Banco de Dados:
  * Principal: MySQL 8.0+ / MariaDB (charset utf8mb4_unicode_ci)
  * Espelho de Backup: SQLite 3 com Journal Mode WAL e modo de transação Deferred

2.2. FRONTEND:
- Framework: Vue.js 3 (Composition API / Options API hibridizadas)
- Build Tool: Vite 8 com Rollup/Rolldown e Hot Module Replacement
- Estilização & UI: Bootstrap 5.3+, Bootstrap Icons 1.13+, CSS Custom Properties
- Notificações & Diálogos: SweetAlert2 customizado com identidade visual Aky
- Utilitários: Axios, Máscaras customizadas para moeda/telefone/CEP/documento

2.3. DESKTOP & DEPLOY:
- Containerização: Docker & Docker Compose com Nginx/PHP Alpine
- Runtime Desktop: Electron 34+
- Empacotador: Electron Builder 25+ (Win-Unpacked x64)
- PHP Embutido: PHP 8.5 NTS x64 com extensões pdo_sqlite, pdo_mysql, curl, mbstring
- Criador de Instalador: Inno Setup 6 (Script Pascal / ISS automatizado)

4. PERFIS DE USUÁRIO E CONTROLE DE ACESSO
================================================================================
O sistema opera com 4 papéis de usuários autenticados mais o acesso público:

1. ADMIN (Administrador Geral):
   - Acesso irrestrito a todas as áreas do sistema.
   - Gestão completa de pedidos: mudança de status, cancelamento, atribuição
     de cozinheiro e de motoboy, reimpressão de cupons térmicos.
   - Gerenciamento de cardápio: criar, editar, pausar produtos, definir promoções,
     ajustar fotos e sincronizar tabelas de preços de pizzas.
   - Gestão de equipe: cadastrar, editar, desativar usuários e redefinir senhas.
   - Configurações do estabelecimento e parâmetros da impressora térmica.

2. ATTENDANT (Atendente / Caixa):
   - Acesso focado no fluxo operacional diário.
   - Visualização e avanço de status dos pedidos em tempo real.
   - Atribuição do pedido a um cozinheiro específico ao mover para "Em Preparação".
   - Atribuição do pedido a um motoboy ao mover para "Saiu para Entrega".
   - Impressão de cupom térmico descritivo para a cozinha.

3. KITCHEN (Cozinheiro / Operador da Cozinha):
   - Acesso dedicado ao painel KDS (`KitchenOrders.vue`).
   - Interface otimizada em visual claro/flex com suporte a Modo TV (texto ampliado).
   - Visualização com destaque máximo para nome do item, ingredientes padrão
     da descrição, personalizações (sabores/recheios/tamanhos) e observações.
   - Filtros por operador: "Todos", "Cozinha Geral" ou tarefas do próprio usuário.
   - Ação de concluir o preparo (movendo o pedido de "Em Preparação" para "Pronto").

4. MOTOBOY (Entregador):
   - Acesso restrito ao painel de entregas (`MotoboyOrders.vue`).
   - Visualiza pedidos atribuídos a ele com endereço, complemento, ponto de
     referência e telefone do cliente com botão direto para WhatsApp e GPS.
   - Ação de confirmação de entrega presencial.

5. CLIENTE (Público / Não Autenticado):
   - Navega pelo cardápio, adiciona itens ao carrinho e finaliza pedidos.
   - Acompanha o rastreamento em tempo real usando o código do pedido (Ex: AKY-20261104-ABCD).
   - Confirma o recebimento e avalia o pedido (nota para a comida, nota para a entrega
     e comentário com opção de privacidade).

  * Seleção de tamanhos (Ex: Pizza Média, Grande, Família).
  * Seleção múltipla de sabores de pizzas com divisão proporcional do valor.
  * Seleção de bordas recheadas (Catupiry, Cheddar, Chocolate, etc.).
  * Seleção de recheios múltiplos para pastéis especiais.
  * Seleção de adicionais (bacon extra, queijo, ovo, hambúrguer artesanal extra).

  * Seleção do tipo de pedido: "Entrega" ou "Retirada no Local".

  * Calculadora de troco inteligente para pagamentos em dinheiro.
  * Finalização via API com persistência no banco e geração de link formatado
    para envio automático dos detalhes ao WhatsApp da loja.

- Botão "Motoboy / Entrega" com modal de busca e vinculação de entregador.
- Botão discreto para impressão térmica do cupom descritivo da cozinha.
- Expansão detalhada do pedido exibindo valores, itens, adicionais e troco.

  * Código do pedido em tamanho grande e tempo decorrido em minutos.
  * Badge de Entrega vs. Retirada.
  * Destaque para o Responsável pelo Preparo com botão rápido para alterar.

  * Destaque com badges para personalizações (sabores, recheios, adicionais).
  * Caixa de alerta destacada para observações de preparo ("Sem cebola", "Mal passado").

- Switch rápido para pausar/ativar produto em caso de falta de estoque.

7. BANCO DE DADOS E RELACIONAMENTOS (MODELAGEM)
================================================================================
O banco de dados é estruturado em tabelas relacionais com índices otimizados:

1. TABELA `users`:
   - `id`: Chave primária auto-increment.
   - `name`: Nome completo do usuário.
   - `email`: E-mail único de acesso.
   - `phone`: Telefone com máscara brasileira.
   - `document`: CPF / Documento do colaborador.
   - `password`: Hash Bcrypt da senha.
   - `role`: Enum ('admin', 'attendant', 'motoboy', 'kitchen').
   - `is_active`: Booleano indicando se o acesso está habilitado.
   - `created_at`, `updated_at`.

2. TABELA `categories`:
   - `id`: Chave primária.
   - `name`: Nome da categoria (Ex: Sanduíches Artesanais, Pastéis, Pizzas).
   - `order`: Ordem de exibição no menu.
   - `is_active`: Booleano de visibilidade.

3. TABELA `products`:
   - `id`: Chave primária.
   - `category_id`: Foreign key referenciando `categories(id)`.
   - `name`: Nome do produto.
   - `description`: Ingredientes e detalhes de composição do item.
   - `photo_path`: Caminho da imagem salva em `uploads/`.
   - `price`: Preço de venda padrão (decimal 10,2).
   - `promotional_price`: Preço especial de oferta (nullable).
   - `is_promotion`: Booleano ativador da promoção.
   - `is_combo`: Booleano que sinaliza combo especial.
   - `is_available`: Booleano que permite pausar o item se acabar o estoque.

4. TABELA `orders`:
   - `id`: Chave primária.
   - `uuid`: Identificador universal único (v4) para espelhamento e sync.
   - `order_number`: Código legível exibido ao cliente (Ex: AKY-20261104-ABCD).
   - `origin`: Origem do pedido ('web', 'desktop', 'balcao').
   - `sync_status`: Status de sincronia ('synced', 'pending').
   - `customer_name`: Nome do cliente.
   - `customer_phone`: Telefone de contato.
   - `customer_document_encrypted`: CPF criptografado para privacidade.
   - `delivery_cep`, `delivery_address`, `delivery_complement`, `delivery_reference`.
   - `status`: Enum ('recebido', 'em_preparacao', 'pronto', 'saiu_para_entrega',
     'concluido', 'cancelado').
   - `motoboy_id`: Foreign key nullable referenciando `users(id)`.
   - `kitchen_user_id`: Foreign key nullable referenciando `users(id)` (Cozinheiro).
   - `payment_method`: 'dinheiro', 'cartao_credito', 'cartao_debito', 'pix'.
   - `needs_change`: Booleano de necessidade de troco.
   - `change_for`: Valor informado para cálculo do troco em espécie.
   - `total`: Valor final do pedido incluindo itens e taxa de entrega.
   - `notes`: Observações gerais do cliente sobre a entrega ou preparo.
   - `motoboy_confirmed_at`: Data e hora da confirmação pelo entregador.
   - `customer_confirmed_at`: Data e hora da confirmação pelo cliente.
   - `food_rating`, `delivery_rating`: Notas de 1 a 5 estrelas.
   - `review_comment`: Texto de feedback do cliente.
   - `allow_public_review`: Booleano autorizando exibição pública da avaliação.
   - `review_show_name`: Booleano autorizando exibição do nome do cliente.
   - `reviewed_at`: Timestamp da avaliação.

5. TABELA `order_items`:
   - `id`: Chave primária.
   - `uuid`: Identificador universal único do item.
   - `order_id`: Foreign key referenciando `orders(id)`.
   - `product_id`: Foreign key referenciando `products(id)` (nullable).
   - `product_name_snapshot`: Cópia estática do nome do produto no ato da compra.
   - `quantity`: Quantidade do item.
   - `unit_price`, `subtotal`: Valores monetários no momento do pedido.
   - `customizations`: JSON contendo adicionais, sabores múltiplos, recheios e bordas.
   - `notes`: Observações específicas daquele item.

6. TABELA `system_settings`:
   - `id`: Chave primária.
   - `key`: Chave identificadora única (Ex: `printer_settings`, `store_info`).
   - `value`: Valor serializado em texto / JSON.

10. ESPELHAMENTO E BACKUP AUTOMÁTICO EM SQLITE
================================================================================
Para assegurar a resiliência operacional contra perdas de dados e manter uma
cópia local pronta para recuperação imediata, o sistema possui um espelhamento
completo para SQLite:

10.1. CONEXÃO E ARMAZENAMENTO:
- Configurada em `laravel/config/database.php` sob o nome `sqlite_backup`.
- Arquivo de destino: `laravel/database/backup/aky_backup.sqlite`.
- O modo WAL (Write-Ahead Logging) e transações assíncronas garantem que a
  operação de gravação seja ultra rápida sem travar o MySQL principal.

10.2. ESPELHAMENTO EM TEMPO REAL (MODEL HOOKS):
- Registrado em `laravel/app/Providers/AppServiceProvider.php`.
- Monitora os eventos `saved` e `deleted` nos modelos:
  * `Order`, `OrderItem`, `Product`, `Category`, `User`, `SystemSetting`.
- Toda inserção, alteração ou exclusão é espelhada de forma isolada em bloco
  `try/catch` pelo `SqliteBackupService.php`. Se o SQLite estiver bloqueado ou
  indisponível, a operação do MySQL NUNCA é interrompida.

10.3. COMANDO DE SINCRONIZAÇÃO COMPLETA:
- Comando de console: `php artisan backup:sqlite`
- Comportamento:
  * Cria o arquivo e pastas caso não existam.
  * Executa automaticamente as migrations na base SQLite com adaptação dinâmica
    de tipos para compatibilidade SQLite / MySQL.
  * Copia todas as linhas de todas as tabelas em transação protegida por upsert de ID.
  * Exibe resumo tabular com as contagens de registros sincronizados.

11. APLICAÇÃO DESKTOP ELECTRON
================================================================================
O projeto conta com um aplicativo desktop nativo para Windows em `d:\cardapio\desktop`:

11.1. ARQUITETURA DO EXECUTÁVEL:
- O Electron empacota o runtime do Chromium, o código do Laravel compilado e um
  interpretador PHP 8.5 portátil completo dentro de `dist/win-unpacked/`.
- Não requer instalação prévia de PHP, Node ou Apache na máquina do cliente.

11.2. FLUXO DE INICIALIZAÇÃO (`desktop/main.js`):
1. Trava de Instância Única: Garante que apenas um processo do sistema rode por vez.
2. Splash Screen: Exibe imediatamente a janela de carregamento personalizada Aky
   Lanches enquanto os serviços sobem.
3. Subida do Backend Portátil:
   * Localiza o PHP embutido em `resources/php/php.exe`.
   * Inicializa o servidor web local do Laravel na porta `8765` com os parâmetros:
     `artisan serve --host=127.0.0.1 --port=8765 --no-reload`.
   * Injeta os caminhos de ambiente `PATH` e `PHP_BINARY` para que os subprocessos
     do Laravel encontrem as extensões do PHP portátil.
   * Aplica proteção de flags `-d opcache.enable=0 -d opcache.enable_cli=0` para
     eliminar conflitos de memória ASLR no Windows.
4. Verificação de Saúde HTTP:
   * Realiza polling na porta `8765`.
   * Assim que a rota `/api/menu` responde HTTP 200, a janela principal é maximizada,
     a splash screen é fechada suavemente e o cardápio/atendimento entra no ar.
5. Backup de Fundo:
   * Dispara o comando `artisan backup:sqlite` em segundo plano de forma assíncrona,
     garantindo que o banco de backup local esteja sempre atualizado.
6. Encerramento Seguro:
   * Ao fechar a janela, o Electron mata de forma forçada o processo do PHP
     utilizando `taskkill /pid ... /T /F`, liberando a porta e a memória RAM.

11.3. ARQUIVO DE LOG:
- Registrado em: `%LOCALAPPDATA%\AKY Lanches\app.log` ou na pasta do executável.

13. GUIA DE INSTALAÇÃO, CONFIGURAÇÃO E EXECUÇÃO
================================================================================

13.1. REQUISITOS DO SISTEMA (AMBIENTE DE DESENVOLVIMENTO):
- PHP 8.2 ou superior (com extensões pdo, pdo_mysql, pdo_sqlite, mbstring, curl, openssl).
- Composer 2+.
- Node.js 18+ e NPM.
- Servidor MySQL 8.0+ ou MariaDB.

13.2. PASSO A PASSO PARA RODAR O PROJETO LOCALMENTE:
1. Navegue até o diretório do backend:
   `cd d:\cardapio\laravel`
2. Instale as dependências PHP:
   `composer install`
3. Instale as dependências Frontend:
   `npm install`
4. Configure o arquivo `.env`:
   Copie `.env.example` para `.env` e configure:
   ```env
   APP_NAME="AKY Lanches"
   APP_ENV=local
   APP_KEY=base64:...
   APP_DEBUG=true
   APP_URL=http://localhost:8000

   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=cardapio
   DB_USERNAME=root
   DB_PASSWORD=sua_senha

   SQLITE_BACKUP_ENABLED=true
   DB_SQLITE_BACKUP_PATH=database/backup/aky_backup.sqlite
   ```
5. Execute as migrations e alimente o banco de dados inicial:
   `php artisan migrate --seed`
6. Execute o espelhamento inicial do banco para o backup SQLite:
   `php artisan backup:sqlite`
7. Compile os assets do frontend:
   `npm run build`  (ou `npm run dev` para desenvolvimento contínuo)
8. Inicie o servidor Laravel:
   `php artisan serve`

13.3. COMO RODAR COM DOCKER (PRODUÇÃO / VPS):
1. Na raiz do projeto:
   `docker compose up -d --build`
2. A aplicação subirá mapeada na porta configurada (padrão 8008 -> 8080).

13.4. COMO TESTAR OU COMPILAR O APLICATIVO DESKTOP:
1. Navegue até a pasta desktop:
   `cd d:\cardapio\desktop`
2. Para compilar a pasta de distribuição unpacked:
   `npm run build`
3. O executável estará pronto em `d:\cardapio\desktop\dist\win-unpacked\AKY Lanches.exe`.

15. MANUTENÇÃO, LOGS E RESOLUÇÃO DE PROBLEMAS
================================================================================

15.1. LOGS DO SISTEMA:
- Logs do Laravel (erros de API, SQL, exceções):
  `laravel/storage/logs/laravel.log`
- Logs do Aplicativo Desktop Electron:
  `%LOCALAPPDATA%\AKY Lanches\app.log`

15.2. O FRONTEND NÃO ATUALIZA APÓS ALTERAÇÃO NO CÓDIGO VUE:
- Causa: Arquivo `laravel/public/hot` gerado pelo comando `npm run dev` que faz
  o Laravel buscar os assets no servidor do Vite em vez dos arquivos compilados.
- Solução:
  Remova o arquivo temporário caso exista e recompile:
  `Remove-Item d:\cardapio\laravel\public\hot -Force -ErrorAction SilentlyContinue`
  `cd d:\cardapio\laravel && npm run build`

15.3. ERRO DE OPCACHE / ASLR AO INICIAR O PHP NO ELECTRON:
- Mensagem: "Fatal Error Opcode handlers are unusable due to ASLR".
- Solução: O script `desktop/main.js` e o `desktop/resources/php/php.ini` já possuem
  as diretivas `opcache.enable=0` e `opcache.enable_cli=0` injetadas para garantir
  estabilidade no Windows.

15.4. PERMISSÕES DE ESCRITA NO BANCO SQLITE APÓS INSTALADOR:
- Caso o banco não consiga gravar dados ao instalar em Program Files, verifique se
  a instalação foi feita como Administrador, garantindo que as diretivas do arquivo
  `desktop/installer/aky-lanches.iss` tenham aplicado `Permissions: users-full`.
